# BEETLE V1.8 — BLUE RC12 Port and Stability Validation

## Scope

Starting from the complete BEETLE **V1.7.14** source and reviewing BEETLE BLUE **V1.0.0 RC12**. BEETLE is a five-synth-plus-one-drum tracker, **not** the BLUE six-drum engine. The original TRK1 V26 project schema, 12 slots, 13 usersample notes, USB audio/clock path, five synthesizers, protected bootloader and original OTA application identity are unchanged.

## Tests executed

- Writable JieLi FM1 V2+USB build: **PASS**, native APP 518,292 bytes / 581,564 max, **63,272 free bytes**.
- Read-only JieLi FM1 hardware-test build: **PASS**, APP 457,952 bytes / 581,564 max; symbol audit **PASS** (forbidden writes not linked).
- Native and WebSimulator HELP: **PASS**, 222 instruction strings, 13 topics, ≤36 glyphs per line, three-card navigation test.
- Felucca battery raw thresholds/filter/hysteresis: **PASS** host C test.
- Storage V2 sample playback: **PASS**, 40,000 PCM frames exact versus native reference, zero host underruns; six sample voices for 44,000 frames; zero read from audio callback in test.
- Storage workspace journal test: **PASS**, 12 slots, 9 interruption points, A/B fallback and foreign data protection.
- Dense song transition / voice budget: **PASS** in RC1.0.11b host test.
- Legacy `run_rc1011b_audio_stability.sh` overall: **NOT PASS** because it expects PCM hash `43c0f1f6` but produces `dd0f3681`. This is preexisting in V1.7.14 source, since `track_chip.c`, `track_mixer.c`, `track_core.c` are byte-identical to that baseline. Do not relabel it as a solved audio issue.
- JS syntax: **PASS** for all inline JS scripts in current simulator, WebInstaller, Project Manager and manager.
- Actual FM1 DMA deadline duration, physical headphone/amp safety, USB recording, battery calibration and OTA/recovery: **NOT TESTED**.

## Selective exclusions

- Do **not** copy BLUE's BDR1 V33 codec, six-drum voices, MONOLITH kit, or global BBK1 user-kit footer: not schema/architecture-compatible.
- Do **not** copy BLUE's full per-slot decoded attack cache: requires staging memory also used by BEETLE's synth project workflow and could violate RAM ownership. The lower-memory generation/CRC and single-pass ISR improvements are transferred independently.
- Do **not** claim DMA DEADLINE can no longer happen: BLUE RC12 itself documents unresolved physical FM1 deadline failures. V1.8 reduces one known ISR hot path, not every possible source of worst-case CPU/flash/USB contention.

## Required physical FM1 acceptance

Back up projects and global samples; verify an independent recovery method. Start at safe low analogue output levels, with no headphones or amplification for the first test. Compare battery icon at unplugged and USB-powered states without interpreting bar count as percentage; test sample triggers/retriggers with all six lanes, eight synth voices, Song Mode, MASTER FX and USB six-stem recording; log longest DMA half-block processing time, fault count, stream stalls and output peaks during at least one extended session. Do not declare release hardware-stable without passing these measurements.
