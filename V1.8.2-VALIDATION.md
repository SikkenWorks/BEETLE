# BEETLE V1.8.2 — stock V15 OTA return validation

## Scope

BEETLE V1.8.2 is based on the complete V1.8.1 source. The code change is restricted to the firmware updater (`ota.c`) and version strings. Audio DSP, native USB audio, project storage, global sample layout, firmware identity `FM-1_2123`, and protected OTA boot assets are unchanged. The README remains a user manual; release notes appear in CHANGELOG.md.

## Root-cause analysis

Before V1.8.2, `etch_ota_available()` rejected the whole outgoing update if the dedicated 0xE0000..0xE4FFF staging area contained a marker not owned by BEETLE/ETCH and was not completely erased. That restriction could prevent the official V15 return after an interrupted update or a firmware-family switch. The V15 route previously authenticated its flash.bin by SHA-256 but the accompanying stock OTA loader used legacy header/CRC constants without a separate cryptographic digest pin.

V1.8.2 recognizes a **pair**: exact original V15 flash.bin SHA-256 (`c1068a403c04a6378a626afb66cc217f72d13f10aa200e983b7a9817cc1dac03`) and original M-VAVE V15 ota.bin SHA-256 (`ef1f2db89b011fa53e71df363f0122de0ea896618c53fb53e8da676322004541`). Both are read from the host **before** erasing any flash. Header and CRC checks still run, including full loader CRC **before** erase. Only this exact pair is allowed to reuse the dedicated OTA staging area; arbitrary third-party loaders still need normal ownership/empty checks. The OTA-loader binary in the outgoing BEETLE release is unchanged.

## Tests and reproducibility

```
python tests/ota/test_v182_stock_restore.py
bash tests/track/run_v181_audio_stability.sh
export JIELI_TOOLCHAIN=/path/to/jieli-linux-toolchains
python firmware/fm1-native/build.py --beetle-storage-lab --updater --usb-audio --beetle-v2
python firmware/fm1-native/build.py --hardware-test
python tools/build_v182_release.py
```

The native OTA replay uses a **synthetic, never-shipped** stock-shaped image and temporary fixture-only SHA pins. It verifies acceptance with empty and foreign/stale staging, refusal of corrupted loader (-25) with **zero erases**, and refusal of a custom image with foreign staging (-15) with **zero erases**. The test cannot establish that the exact genuine M-VAVE file or the physical firmware updater works; it intentionally makes no such claim.

To run a full native host replay of the exact M-VAVE V15 file, obtain its unmodified 699,956-byte `FM-1.fwsc` (SHA-256 `db1642b2b6fa5c2cccb11ffd13878068bb28601678d3644049f99dc40e7edb8a`) and run:

```
python tests/ota/test_v182_stock_restore.py --official-v15 /path/to/FM-1.fwsc
```

The test checks M-VAVE's original package hash and independently replays BEETLE's *production* OTA code with a clean and stale staging area. The official file is not redistributed in this archive.

## Physical tests outstanding

1. Back up all 12 BEETLE project slots, plus the global U01–U13 sample bank. Use independent firmware recovery with a verified backup.
2. On a controlled FM1, install this exact V1.8.2 firmware with a known recovery method and verify `FM-1_2123` through USB-MIDI.
3. In The Firmware Hub, choose **Back to official V15**. The Hub should verify its SHA-256, BEETLE should perform its own checks, M-VAVE's loader should start, and the FM1 should return as `FM-1_015` after writing.
4. Test again with a controlled interrupted staging attempt, **not** by deliberately unplugging during whole-flash writes without hardware recovery equipment. Verify the documented OCT− USB rescue route independently.
5. Test project/sample restore after reinstalling BEETLE. Never assume that switching to stock preserves user data.

No claim that OTA always succeeds, that V16 is supported, or that DMA safety is physically proven is made here.
