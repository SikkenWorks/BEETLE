# BEETLE V1.3 validation and limitations

Baseline: complete V1.2 zip. No real FM1 USB recording, electrical USB trace or hardware performance measurement was available. Results below are software-only.

## Punch-In and Song Mode

REC captures fresh physical pressed/released edges after PLAY has started. Source routing uses `track_song_punch_pattern` (Song Chains CH1 reference), not the unrelated tracker cursor pattern. On Song position changes, recorded held FX close in the old pattern and start in the next CH1 source. Each source pattern owns its own 24-event Punch clip (unchanged V19 data schema). Re-recording a particular FX replaces only that FX's old events in the source, retaining all other effects. Initial transport/changed Song row replay is evaluated without borrowing an ON from the last step of a different timeline; true repeated-loop sustain remains possible. STOP safely closes recorded held FX. Existing clips may still contain prior unintended data; re-record affected FX to clear its lane.

**Important scope:** Song positions that reference the same CH1 pattern continue sharing that pattern's Punch events. The 64 Song rows do not have independent 64 new FX timelines. An empty CH1 (`--`) cannot own a Punch recording. These are existing V19 storage-model limits.

## Audio and panning

Voice headroom curve is a fixed Q8 table, no per-sample sqrt or heap allocations. Centered L/R gain is unchanged from V1.2; panning uses independent equal-power Q8 gains computed once per render chunk for 5 synth lanes and the drum lane. The USB buffer taps the same processed `left`/`right` post-master stereo samples that feed analogue DMA, and the UAC packet code packs independent 16-bit L and R samples. MASTER reverb may add some cross-channel energy when enabled; the dry panning isolation tests run without reverb.

All prior waveform loudness calibration and USB clock resampler remain included. The V19 project layout is unchanged. No new flash region has been allocated.

## Measured V1.3 regression results

- Native C renderer, one VA note: **6089.11 RMS**; same settings with a three-note chord: **6169.80 RMS**. This is about **0.11 dB** difference for this one fixed test; it is not a guarantee for every chord, patch or MASTER setting.
- Independent left and right native PCM tests verify hard-left and hard-right routing for **synth and drum** channels. A static path check confirms the two post-master samples reach the UAC stereo tap in the correct order. A physical Windows USB recording has not been evaluated.
- Punch-In regression covers real new key-on, rejected orphan release, no stale loop-edge FX at transport start, a re-recorded effect without duplicate legacy events, and Song-CH1 recording source selection.
- Earlier V1.2 regression covers 12 oscillator types and 5 VA waveshapes, and a **120 s / 5,292,000-frame** USB sample-clock simulation with no simulated buffer errors.
- Preserved 64-position Song Chains and V19 project compatibility. Firmware image/app audit, 12 HELP chapters, browser JavaScript syntax and pinned WebInstaller SHA-256 checks pass.

## Tests and hardware warnings

Run `bash tests/track/run_v13_regression.sh` in the source root; the separate JieLi toolchain is required for a native target build. Correct post-master stereo packing and all native audio and project tests are software checks, not captured FM1 audio.

No physical FM1 USB-C stereo capture, clipping/jitter/endurance, stock firmware restoration or independent hardware recovery was performed. The OTA lab storage-enabled firmware remains **EXPERIMENTAL**, can overwrite device storage after destructive initialization, and can brick the FM1. Do not install without verified full flash backup and a separately demonstrated recovery path. The WebInstaller does not make a complete device backup.
