# BEETLE V1.3.7 — native FM1 SETTINGS + all-in-one Manager

Date: 2026-10-20. **Experimental / software-only.** No FM1, DAW, or USB controller was connected during validation.

## Root cause: on-device SETTINGS jumps to TRACKER

Native `track_runtime.h` assigns SETTINGS page `38` (`BEETLE_SETTINGS_PAGE`). The previous `track_runtime_validate()` whitelist accepted pages 0–30, 32, and 33–37, **not 38**. Immediately after a physical SEL press entered page 38, `track_fm1_draw()` called `track_runtime_validate()` and reset `track_page=0`, the Tracker. The same validator is called on every input poll. This explains why the browser simulator worked but the physical firmware did not.

Fixed by routing page validation through `beetle_ui_page_valid()` in `beetle_settings_nav.h` and accepting the SETTINGS page in both native validation sites. Separate SEL entry/release/toggle handling is retained; HOME returns to PROJECTS.

## Limits and hardware caution

Software and link-time checks do **not** establish that physical FM1 SEL, USB re-enumeration, six-channel multitrack capture, updater, firmware installation or stock recovery operate safely on a real unit. This firmware can overwrite prior storage or brick a device; hardware testing, independently verified backup and proven recovery are still required. Do not mistake the emulator label or a passing simulated test for on-device confirmation.
