# BEETLE V1.8.3 — Dual flash-chip support (experimental)

## Supported JEDEC IDs

| Chip | JEDEC ID | Capacity |
|---|---|---|
| Puya P25Q80 | `0x856014` | 1 MiB |
| UCUN UC25HQ80 | `0xB36014` | 1 MiB |

The known-chip policy is identical in the application and the included, locally compiled Felucca-lineage **app-only** update loader. Unknown JEDEC IDs and failed reads are not permitted to erase or program NOR. The ID is sampled once per boot on the native app's stopped storage/OTA write path, not from the realtime audio ISR. In the loader, it is checked before the first app update session. Read-only scans are still permitted.

**BEETLE V1.8.2 did not have an active Puya-only JEDEC comparison in the native app**, except for a stale comment in `hal/fm1_flash.h`. Therefore the original claim that all BEETLE V1.8.2 saves were blocked by that specific comparison could not be reproduced from source. In V1.8.3 both chips are explicitly allowed *and other types are blocked* on the write paths. Physical UC25HQ80 read/write behavior still requires testing.

## Update loader changed for the first time

The new `.fwsc` contains a rebuilt Felucca-lineage app-only loader (`firmware/loader`) instead of the original inherited binary M-VAVE loader. Its original work is copyright (C) 2026 Leo Kuroshita, Hügelton Instruments, GPL-3.0-only; its package builder also uses Felucca's GPL LZ4 implementation. The loader preserves its own 1 MiB app-only write bounds (`0x4000..0x92FFF`) and checks the expected FM1 chip key, the entire incoming UFW CRC and each app sector. It does **not** replace the protected `0x0000..0x3FFF` boot area. No project/sample sectors may be erased by this loader. A generic `0x9F` JEDEC probe checks the two allowed IDs before accepting a session. The stock-V15 restore path remains an independently SHA-pinned V15 flash+loader pair: this release does not edit the official stock loader.

**IMPORTANT:** A compiled loader is not hardware-proven. There is risk of failure or bricking during the two-stage update, particularly on UC25HQ80 units with an older, incompatible updater already installed. Use independent ROM/UBOOT rescue, verify a complete backup, and obtain a hardware test before treating the build as safe for routine updating. An installed older loader cannot be repaired merely by offering a newer `.fwsc` if its transfer itself is blocked.

## Validation

`python tests/flash_id/test_v183_flash_ids.py` validates the two known values, unsupported ID rejection, source wiring, and both loader packaging headers. `python tests/ota/test_v183_ota_acceptance.py` replays the exact new `.fwsc` against the production V1.8.2 OTA stage to confirm eligibility and no unsupported loader or application format changes. `python tools/build_v183_loader.py` compiles the app-only loader from complete GPL-covered source.

Native app build, full read-only build, storage and audio tests are documented separately in `V1.8.3-VALIDATION.md`. USB transfer and flash write have not been hardware-tested for either flash chip in this execution environment. Verify device-specific restore functionality before testing firmware switches.
