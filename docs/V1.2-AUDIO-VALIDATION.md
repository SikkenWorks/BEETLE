# BEETLE V1.2 | USB audio and waveform level analysis

## What was actually examined

This release was developed from the user's complete V1.1 (`1.01 RC1.1`) firmware source, not from an FM1 hardware capture. No raw USB recording, device USB trace or real-device CPU measurement was provided. Findings and results here are from direct C source review, native C-rendered PCM, USB-clock simulation, cross-compilation and firmware/installer consistency checks.

## USB audio: specific source-level findings

- The inherited UAC1 capture path streamed 16-bit stereo PCM on EP4, but used an extra/missing **whole sample in a USB packet** when the independently clocked FM1 ring fill crossed a window. The cited codec rate was approximately 44,117.6 frames/s while the USB host format is nominally 44,100. Although USB packet-size correction can be legitimate, the legacy controller used the last block-boundary fill estimate and could produce unnecessary short-term packet-size modulation. That is a possible source of audible artifacts; without a real capture it cannot be proven to be the sole cause.
- V1.2 keeps the regular 44/45 samples-per-millisecond **44,100 Hz host** packet sequence. It now bridges the physical audio-clock difference by fractional Q16 ring reading with **bounded, smoothed** read-speed correction and stereo linear interpolation. There is no automatic per-voice AGC, limiter, noise gate, USB gain or FIR processing in this path.
- Both stereo channels are sampled from the existing post-master output, and are interpolated from the same read fraction. The analog and USB MIDI paths are retained. **USB Audio Class 1** is input to the computer, not an output sink.
- The USB runtime state was moved into the existing, boot-zeroed `.usb_audio_ram` region to keep base RAM below its linker limit. The optional 48 kHz FIR mode remains disabled for the release.

## Waveform and instrument level findings

A deterministic host test directly invokes `track_chip_render()` with MIDI note 60 (C4), velocity 110, attack 0, sustain 100, mixer lane volume 100 and clean default patches. After the initial transient it measures 20,480 mono samples per instrument. Levels below refer to numeric PCM RMS, **not** user listening loudness, analog line output or equal-loudness across the entire keyboard.

| Type | Original RMS | V1.2 RMS |
| --- | ---: | ---: |
| DMG Pulse | 17,028 | 6,983 |
| Retro Wave | 7,285 | 6,972 |
| VA OSC | 5,311 | 6,701 |
| VA OSC2 | 3,849–4,000 (shape settings vary) | 6,677 |
| SID 6581 | depends on selected wave A/B | 6,806 |
| SID 8580 | depends on selected wave A/B | 6,879 |
| SID Dirty | depends on selected wave A/B | 6,774 |
| SID Bass | 5,161 | 6,995 |
| SID Noise | 3,374 | 6,918 |
| NES Pulse | 8,314 | 6,950 |
| NES Triangle | 9,861 | 6,972 |
| NES Noise | 7,275 | 6,934 |

The measured V1.2 fixed-configuration spread is ~6,677 to ~6,995, under 0.5 dB RMS. The same host test measures all five VA shapes through both VA OSC and VA OSC2. Wave and type correction uses bounded, static Q8 multipliers; it does **not** dynamically raise sustain tails or flatten modulation. Different distortion, filter cutoff, resonance, pitch, pulse width, oscillator blend or stacked voices can still change subjective loudness and clipping.

## Tests run

- Native JieLi pi32v2 compilation: `python firmware/fm1-native/build.py --beetle-storage-lab --updater --usb-audio`. App linker budget and app-header audit passed.
- `bash tests/track/run_v12_audio.sh`: native oscillator + VA wave RMS/headroom regression, UAC drift simulation, 64-row Song Chains transition test, 4–8 voice fallback test, V19 song migration, HELP chapters, firmware/SHA-pinned installer and both simulator JavaScript syntax checks.
- Clock model: 120 seconds, codec 44,117.6 Hz vs USB host 44,100 Hz; 5,292,000 delivered stereo frames, zero ring underrun/overrun in the **simulated workload**. This is not a host driver test and does not model worst-case FM1 IRQ collisions.
- The original protected first 16 KiB and embedded OTA loader compared byte-for-byte to the V1.1 image. V19 project schema and memory regions are unchanged.

## Hardware limitations and validation checklist

**NOT hardware-certified, do not infer safe OTA flashing.** A real FM1, DAW and long stereo USB recording are necessary to confirm audible quality and isolate remaining noise. Record a 30–60-second clean reference tone/sustain from both USB-C and the analog output, then a full Song Chains/drum/MASTER FX stress playback. Compare peak/RMS and listen for periodic ticks, drift, missing frames, clipping or electrical hum; inspect UAC `UND`, `OVER`, `MISS`, `STALL` counters and ALNK late/blocked metrics on-device. Test start/stop, USB reconnect, PC sleep and recording applications at native 44.1 kHz 16-bit stereo. A reliable full-flash backup and independent stock recovery must be confirmed **before** flashing; the WebInstaller does not establish recovery safety.
